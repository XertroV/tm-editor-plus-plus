# Foggers / particle GPU models — custom textures

Ghidra (`Trackmania.exe` @ `0x140000000`) 2026-08-24.

There is no string `Fogger`. Official “foggers” are **particle emitters** (`CPlugFxSystem` → `CPlugFxSystemNode_ParticleEmitter` → `CPlugParticleEmitterModel` / `CPlugParticleEmitterSubModel`).

| Offset | Member |

`Register_CPlugParticleGpuModel_ClassInfo` (`0x140041ee0`).

The GpuModel analysis screenshot (particle params, bitmaps, PreLightGen) is this nod, not a `CPlugMaterial` on a mesh.

## Can we put custom textures / effects on a custom fogger?

**Yes, in principle.** A custom item that embeds (or refs same-tree) a `CPlugFxSystem` whose emitter submodel has a **cloned `CPlugParticleGpuModel`** with your bitmaps / shader params.

How:

1. Start from an official fogger/smoke item (or E++ fire/cloud prefab that already has a `CPlugFxSystem`).
2. Duplicate the `CPlugParticleEmitterSubModel` and its `GpuModel` (do not leave GameData fids — mode 10 will reject them; ZeroFids / user bitmaps).
3. Point GpuModel bitmaps at user `.Texture.Gbx` / `.dds` in the item tree.
4. Tune GpuModel params (the same fields as the particle editor: lifetime, color, wind, etc.).
5. Keep the rest of the prefab (DynaObject + optional kinematic) as a carrier.

Not a material `PhysicsID` swap. Not `CPlugMaterialFxDynaMobil` (visual FX class `0x09082000`, unrelated).

## Nod-or-string texture (the fog-cloud bitmap)

The “string **or** nod” texture lives on **`CPlugParticleGpuModel`**, not on `CPlugFxSystem` / `CPlugParticleEmitterSubModel`.

- `CPlugFxSystemNode_ParticleEmitter` (`0x2F0C4000`) archives `Model` as a plain `GbxNodeRef` (`CPlugParticleEmitterModel`).
- SubModel chunk **`0x090B203A`** (ver 1) is two nod-refs: `GpuSpawn`, `GpuModel`.
- The dual field is GpuModel chunk **`0x090C6002`**.

Archive: `CPlugParticleGpuModel_SerializeChunkBody` (`0x14057aab0`, vtable `+0x78`). Chunks `0x090C6000`–`0x090C6003` then `FACADE01` (`CPlugParticleGpuModel_EnumerateChunkId` @ `0x14057aa50`). Current writer version for `0x090C6002` is **`0x16` (22)**.

### Rule

| Chunk version | On disk after the leading `u32` version + `float` at `+0x98` |
|---|---|
| **≤ 6** | Always a **nod-ref** `CPlugBitmap` (`GbxArchive_SerializeTypedRef_CPlugBitmap` @ `0x14013de80`, class `0x09011000`) into **`GpuModel+0x70`**. |
| **≥ 7** | `u32 isTextureFid` (gbx-py name; writer seeds it from **`GbxArchive+0x18`**), then **either** a nod **or** a string. |

`isTextureFid == 0` → archive vtable `+0x8` nod-ref, required class **`0x09011000` `CPlugBitmap`**, store at `+0x70`.

`isTextureFid != 0` → length-prefixed **fid path string** (not a lookback string): `GbxArchive_SerializeFidPathString` (`0x140906350`).

- **Write:** `bitmap+0x8` (`CSystemFid*`), `CSystemFid_ResolveAlias`, folder walk `FUN_1408f98a0` / `FUN_1408f9740` (parent `fid+0x18`), `GbxArchive_WriteString32_FromMwString`.
- **Read:** `GbxArchive_ReadString32_IntoMwString`, strip `'?'` (`FUN_140106560` / `FUN_140105440`), `CSystemFids_ResolvePath(g_CSystemFids)` → `CSystemFid*`. If `archive+0x10==0` (read) and `g_ClearBitmapChunk36And38RefsBeforeArchive==0`, `FUN_140248310` = `CSystemFids_PreloadFidScoped` then vtable `+0x20` must accept class **`0x09011000`**. That loaded `CPlugBitmap*` replaces `GpuModel+0x70`. Failed / empty path clears `+0x70`.

So the string is a **fid path / filename** resolved through the system fid tree into a **`CPlugBitmap`**, then used as the fog-cloud / particle texture. It is not a raw GPU bind of the `.dds` bytes.

Later bitmaps in the same chunk are **always nod-refs** (`SerializeTypedRef_CPlugBitmap`):

| Version | Slot | Offset |
|---|---|---|
| `> 8` | texture2 | `+0x78` |
| `> 11` | texture3 | `+0x80` |
| `> 17` | texture4 | `+0x88` |

Same chunk, fog-specific fields (gbx-py names; Ghidra `SerializeU32` at these offsets): `IsFogEmitter` `+0xfc` and `FogEmissionRate` `+0x100` when version `> 15`.

gbx-py (`~/src/gbx-py/src/gbx_structs.py`) already models this as `isTextureFid / GbxBool` then `IfThenElse(..., GbxString, GbxNodeRef)`.

## Official Stadium.pak names (strings only)

No standalone uncompressed `CPlugParticleGpuModel` / `CPlugFxSystem` / SubModel GBX in `Packs/Stadium.pak` (those bodies sit inside compressed parent items). Visible names:

| Kind | Names |
|---|---|
| Show items | `ShowFogger16m`, `ShowFogger8m`, `ShowFoggerWithLight16m`, `ShowFoggerWithLight8m` |
| FxSys refs (from Technics items) | `Fogger16M.FxSys`, `Fogger8M.FxSys`, `FoggerSpot`, `Smoke.FxSys` |
| Prefab refs | `Fogger16M.Prefab.Gbx` (also listed next to `Speaker.Prefab.Gbx` / `LightRamp8m.Prefab.Gbx` in uncompressed `CPlugPrefab` `0x09145000` catalog blobs) |
| Bitmap | `FoggerSmoke.dds` under folder token `Image` |

`FoggerSmoke` GBX @ pak `0x5c612c40` is a 359-byte uncompressed **`CPlugBitmap` `0x09011000`** (chunks `0x09011019`…`0x09011038`, `FACADE01`). `prefab-tools dump` has no typed parser for that class; ref-table identity is `Image`, file name `FoggerSmoke.dds`. That is the official fog-cloud bitmap a GpuModel string/nod would resolve to — not a particle GpuModel file.

Particle GpuModel / FxSys files are **not** extractable as small standalone GBXs from the pak without the encrypted TOC. `prefab-tools support` has no particle / FxSystem rows.
