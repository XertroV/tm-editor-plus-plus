# Mesh UVs: where they live, how to translate them, and how to batch-save

Ghidra (`Trackmania.exe` @ `0x140000000`) + live validation 2026-09-03. Live harness:
`spike-live-add-kinematic-ao` tools `kinAo.DumpVertexStreams`, `kinAo.TranslateUVs`
(`src/VertexStreams.as`, `src/UvTranslate.as`). Companion: [`2026-09-03-SaveItemModelAsCall.md`](2026-09-03-SaveItemModelAsCall.md)
(the save primitive), [`2026-09-03-Solid2SmoothNormalsPersistence.md`](2026-09-03-Solid2SmoothNormalsPersistence.md)
(stream layout, GPU refresh path).

## Short answer

UVs are per-vertex attributes in each `CPlugVisualIndexedTriangles`'s `CPlugVertexStream`, not a
material property. There is no per-material UV transform on Solid2 items. To translate UVs:

1. For each visual: `stream = vis+0xC0` (inline stream ref), descriptor with semantic **10**
   (`TexCoord0`) in the descriptor list at `stream+0x40` (stride 0x10, sorted by semantic).
   `pCpuData = desc+0x00`, source stride = bits 18..27 of `desc+0x08`. Format **1 = Float2**.
2. `u,v` at `pCpuData + i*stride` (+0, +4) for `i < stream+0x30`. Add the offset in place.
3. Save with `GbxArchive_SerializeNodToFid(fid, item, 10)` (AsCall). The serializer copies the
   descriptor bytes, so the written UVs are exactly what is in the CPU blob.

Semantic **11** (`TexCoord1`) is the lightmap UV set. Do not shift it.

Live (`BF2_Crown.Item.Gbx`, 4 visuals, one stream each, no shared source):

```
stride 40: Position f3 @0 | Normal dec3n @12 | TexCoord0 f2 @16 | TexCoord1 f2 @24 | TangentU dec3n @32 | TangentV dec3n @36
mask 0x28002841
```

Batch `du=0.1, count=3` wrote `Items\AsCallUv_{1,2,3}.Item.Gbx`; a fresh reload of file 2 shows
`TexCoord0` u-range shifted by exactly `+0.2` on every visual, `TexCoord1` untouched, and the source
item restored afterwards.

## Layout reference

### Vertex attribute semantics and formats

From `CPlugVertexDecl_AppendPackedLayoutMaskNames` (`0x1404081f0`) and
`CPlugVertexStream_OrLayoutMaskBit` (`0x140447f90`):

| Semantic | Name | Semantic | Name |
|---|---|---|---|
| 0 | Position | 9 | Color1 |
| 1 | Position1 | 10..17 | TexCoord0..7 |
| 2 | TgtRotation | 18 | TangentU |
| 3 | BlendWeight | 19 | TangentU1 |
| 4 | BlendIndices | 20 | TangentV |
| 5 | Normal | 21 | TangentV1 |
| 6 | Normal1 | 22 | Color2 |
| 7 | PointSize | | |
| 8 | Color0 | | |

`CPlugVertexStream_ElementSizeByFormat` (`0x141a6df20`, u32[17]): format 0 Float1 = 4,
**1 Float2 = 8**, 2 Float3 = 12, 3 Float4 = 16, 14 Dec3N = 4 (others: 4,4,4,8,4,4,8,4,8,4,4,4,8).

Layout mask (`stream+0x3C`): TexCoordN occupies two bits at `0x1800 << (2N)`; the pair encodes
the format (Float2 sets the high bit of the pair). Not needed for editing.

`CPlugVertexStream_FindAttrDescBySemantic(stream, sem)` (`0x140448340`) is the native lookup;
E++ already has the AngelScript equivalent `VisualNormals::FindStreamAttr(vis, semantic, ...)` in
`src/Components/ItemEditor/IE_Visual.as`.

### Which visual uses which material

`CPlugSolid2Model+0x158` = ShadedGeoms vector (count at `+0x160`, stride 16):
`{visualIndex, materialIndex, lodMask, flags}`. Material index refers to `+0xF8` UserMaterialInsts
(stride 0x18) when that vector is non-empty, else `+0xC8` CPlugMaterial refs. Crown: 4 records,
vis i -> mat i, lod 1, flags 1. This is the mapping to offer "shift UVs of material X" in a UI.
(`Dev.as` currently labels `0x158` as "buf of indexes or something".)

Other Solid2 fields confirmed by the Ghidra struct `CPlugSolid2Model_PrefabClosure_CurrentBuild`:
`+0xA8` visuals, `+0xB8` unknown vector (empty on the crown), `+0xC8` materials, `+0xD8` material
ids, `+0xF8` user material insts, `+0x208` active materials, `+0x298` lightmap-UV payload.

### Stream fields used

| Offset | Field |
|---|---|
| `stream+0x28` | shared-source stream (if non-null the bytes belong to another stream; edit that one, or refuse) |
| `+0x30` | logical vertex count (use this, not `+0x34`) |
| `+0x38` | flags: bit0 static, bit1 renderer dirty, bit4 suppress callback |
| `+0x40/+0x48` | descriptors / count |
| `+0x50/+0x58` | interleaved CPU blob / size |

## Live preview (not yet validated from AngelScript)

Writing the CPU blob alone does not change what is rendered; the GPU buffer is a copy. Every native
mutator uses the same sequence (`CPlugVertexStream_SetIsStaticAndQueueGpuRefresh` `0x140448390`,
`FUN_140448410`, `FUN_140448470`, `InsertVertexRange`, ...):

```c
old = stream->dwFlags;                       // +0x38
... mutate CPU storage ...
if ((old & 2) == 0) {
    stream->dwFlags = old | 2;
    if ((old & 0x10) == 0 && g_ctx && g_cb) g_cb(g_ctx, stream);
}
```

`g_ctx` = `0x14201E5C8`, `g_cb` = `0x14201E5D0` (= `Vision_QueueOrRefreshVertexStreamRenderWrapper`
`0x140980640`). The callback returns immediately when `stream+0x18` (render wrapper) is null, so it
is a no-op for a preloaded, non-rendered item, and only meaningful inside the item editor (or with
the item placed in a map). It either refreshes at once or queues the stream for the viewport's
out-of-render drain, which uploads `+0x50` again (`RenderVertexStreamBuffer_UploadCpuMirror`).

Plugin-side plan for a mesh-modeler-style preview:

1. UI: nvg 2D UV map. Draw each selected visual's triangles (index buffer, E++
   `VisualNormals::SnapshotTriangleIndices`) in UV space over a unit square; drag = du/dv.
2. Apply: rewrite `TexCoord0` in place for the visuals of the chosen material (ShadedGeoms).
3. Refresh: set flags bit 1 if clear, then `AsCall::Invoke(cb, ctx, streamPtr, 0, 0)` with both
   globals read via pattern-anchored addresses. Untested live: needs the item editor open. Fallback
   that needs no native call: save + reopen the item (`ItemEditor::SaveAndReloadItem`), which is
   how E++ handles normals today.
4. Save: the AsCall recipe. For a batch, snapshot original UVs, write `orig + k*du`, save
   `Items\Name_k.Item.Gbx` with the ident fixed to the file name, then restore the originals and
   rebind the source nod to its own fid (the serializer rebinds `nod+0x8` to the last destination).

## Gotchas

- `SerializeNodToFid` rebinds the nod to the destination fid. When batch-saving from a cached
  source item, rebind it to the source fid afterwards (`nod+0x8`, `fid.Nod`) or the next
  `Fids::GetUser(source)+Preload` returns the mutated cache.
- Shared streams (`+0x28 != 0`): editing writes through to every visual sharing the source.
- `+0x34` is allocation, `+0x30` is the real count.
- A visual whose UVs are all the same point (crown visual 3: `0.6189, 0.6872`) is a flat-colour
  region; shifting it moves the sample point on the texture. Expected, not a bug.
